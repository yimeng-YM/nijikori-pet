**1. [P1] 两条文件编辑路径会截掉大文件尾部**

位置：`main.py:864`、`main.py:907`、`fs.py:210`、`fs.py:251`。

`replace_in_file()` 最多读取 400,000 个字符；`edit_lines()` 通过 `read_text_auto()` 最多读取 2,000,000 个字符。两者随后都用 `w` 模式把读取到的前缀覆盖回原文件，没有判断是否读完整个文件。只要修改命中前缀，超出部分就丢失，而且返回 `status=success`。参数名虽然叫 `max_bytes`，文本流的 `read(n)` 实际限制的是字符数量。

复现：分别在两种阈值以上的临时文本末尾放置 `TAIL_SENTINEL`，仅修改首行；两次调用都返回成功，尾部标记均消失。已有备份只能帮助恢复，不能消除该错误。

建议：编辑前完整读取；超过允许编辑的大小则明确拒绝，不允许对截断内容回写。采用同目录临时文件和 `os.replace()` 提交写入，保留编码与换行；备份失败应返回明确状态。回归验证应断言未修改区域逐字节保持一致。

**2. [P1] 定时命令绕过工具禁用与命令确认**

位置：`main.py:7567`、`main.py:8180`、`main.py:8593`。

普通工具经过 `execute_tool_call()` 的禁用检查，命令分支还会检查确认开关。定时任务却在 `_fire_scheduled_task()` 中直接调用 `run_command_visible()`；创建任务的路径也没有针对命令内容做对应授权检查。因此关闭 `run_command` 后，同一条命令仍可通过 `set_scheduled_task(task_type="run_command")` 执行。

复现：配置 `disabled_tools=["run_command"]` 且开启命令确认。普通调用被拒绝；调用定时执行入口时，模拟命令启动器仍被调用一次。

建议：统一普通调用与定时调用的权限入口；执行时重新检查工具是否启用。对无人值守任务，在创建或修改时确认具体命令并保存授权范围，修改目标后使旧授权失效。共享检查应覆盖网页、文件、锁屏等其他定时动作。

**3. [P1] 无效配置会被当作默认配置载入并覆盖原设置**

位置：`main.py:4050`、`main.py:4951`、`main.py:4919`。

`load_config()` 吞掉 JSON 读取异常并返回默认配置。热更新无法区分“有效配置”与“解析失败”，直接清空并替换内存配置。当编辑中的文件暂时不完整、JSON 有语法错误或编码不符合预期时，API Key、模型和提醒等设置会被重置，下一次保存再把默认值落盘。

复现：内存配置包含测试用 Key、模型和提醒，把隔离的配置文件写成单个 `{`，执行热更新和保存；原 Key、模型、提醒均未保留。

建议：加载返回明确的成功或失败结果；解析或校验失败时保留最后一份有效配置，提示错误并稍后重试。保存改为原子替换，增加配置结构和字段类型校验。不要把临时读取失败解释为恢复默认值。

**4. [P1] 复制操作可无确认覆盖已有文件**

位置：`main.py:8061`、`main.py:986`。

批量文件操作的确认列表只包括删除、移动和重命名。复制却使用 `shutil.copy2()` 或 `copytree(..., dirs_exist_ok=True)`，目标冲突时会覆盖文件。用户即使开启操作确认，也不会看到这一覆盖行为的提示。

复现：开启确认，将一个临时文件复制到已存在的目标文件；确认回调执行次数为 0，原目标内容被替换。

建议：先解析实际目标路径并列出冲突，包括“文件复制进目录”和目录合并中的同名文件。默认拒绝覆盖，或将具体冲突纳入现有确认流程，并为覆盖内容建立备份。

**5. [P2] 转义字符写错，导致编码识别和行号反馈失真**

位置：`main.py:426`、`main.py:449`、`main.py:568`、`main.py:912`。

字节检查使用了 `b"\\xef\\xbb\\xbf"`、`b"\\xff\\xfe"`、`b"\\x00"`，匹配的是反斜杠组成的文本，而不是真实 BOM 或 NUL 字节。行号统计也使用了 `"\\n"`，没有计算真实换行。主程序与 `pet_tools` 还有两套不同实现，行为已经分叉。

复现：UTF-16 文本被当成 UTF-8 成功返回，内容带替换字符和 NUL；修改第 2 行时，结果报告变更在第 1 行。按行读取的返回内容也没有真实换行。

建议：修正为实际字节和换行字面量，统一文本读取辅助函数；识别 UTF-16 BOM 应先于 NUL 二进制判断。编辑路径遇到解码错误应拒绝写入，避免把 `errors="replace"` 产生的损坏内容保存回文件。

**6. [P2] 分页续读会跳过尚未展示的内容**

位置：`main.py:553`、`main.py:569`、`main.py:583`。

函数先按整批候选行计算 `end_line`，然后才按 `max_chars` 截断返回内容。续读提示仍使用截断前的行号，调用方按照提示读取就会漏掉中间内容。另外 `total_lines` 只统计固定读取窗口，超过读取窗口的文件无法通过增大 `offset` 正常访问后半部分。

复现：100 行临时文件，`max_chars=200`；返回只够展示几行，却提示“本次显示第 1–100 行，续读 offset=101”。

建议：按实际返回的完整行计算 `end_line` 和 `next_offset`；明确区分实际文件总行数与本次扫描行数。按行流式跳过 `offset` 后再读取，保证分页拼接既不丢行也不重行。特别长的单行应有明确的续读策略。

**7. [P2] 命令失败被归一化为成功**

位置：`main.py:322`、`main.py:9247`。

`run_command_capture()` 在命令正常退出后固定返回 `status="success"`，不考虑退出码。`_normalize_tool_result()` 又只根据该状态判断成败，所以测试、编译或脚本退出非零时仍得到 `ok=true`、`isError=false`，误导后续工具循环和日志。

复现：执行无副作用的 `exit /b 7`，结果为 `exit_code=7`、`status=success`，归一化后仍是 `ok=true`。

建议：非零退出码返回明确的失败状态与错误类型，同时保留 stdout、stderr 和退出码。区分“进程成功启动”和“命令成功完成”；在归一化层补充一致性检查。

**8. [P2] 截止日期没有约束实际执行时间**

位置：`main.py:3868`、`main.py:3890`、`main.py:8552`。

`_next_due()` 只比较基准时间 `after` 与截止日期，没有比较最终算出的候选执行时间，因此能排出截止日期之后的任务。到期检查即使发现不再允许安排下一次，也依然无条件把当前任务提交执行；应用长时间关闭后重启可能补执行已经过期的任务。

复现：2026-09-05 创建每周二任务，截止 2026-09-06，下一次执行时间仍为 2026-09-08。另一个已经超过截止日期的到期任务仍进入执行队列。

建议：先定义截止日是否包含当日，再用统一截止时间同时校验候选时间与实际执行时间。为启动时的过期任务明确补执行或跳过策略；所有循环类型共用校验。

**9. [P2] 被新消息中断的旧请求仍能覆盖新对话界面**

位置：`main.py:9635`、`main.py:9655`、`main.py:9665`。

正常回复的 UI 回调检查 `my_turn`，异常和余额回退回调没有相同检查。旧请求在阻塞的网络读取中被新消息取消，随后以普通网络异常结束时，会进入这些未受保护的回调，将旧错误或旧余额答复显示到新一轮对话中。

复现：模拟第一轮等待期间发送第二轮消息，再令第一轮抛出超时异常。第一轮取消事件已设置、当前轮次为 2，旧错误仍被显示。

建议：为成功、异常、回退、流式展示和历史写入统一应用轮次与取消检查，检查应发生在 UI 回调真正执行时。工具及图片暂存状态也应归属于具体轮次，避免多个工作线程共享当前轮状态。

**10. [P2] Harness 监控开关打开后不一定启动监控**

位置：`main.py:6053`、`main.py:6062`、`main.py:10025`。

控制中心的开关只修改布尔值并保存，没有启动监控线程。启动时关闭监控的用户，稍后打开开关不会开始轮询。原有循环在关闭开关后退出，但 `_harness_monitor_started` 没有重置，也阻止后续可靠重启。

复现：从关闭状态调用 `_cc_set_harness_monitor(True)`，配置变为开启，但线程工厂调用次数为 0。

建议：通过统一的启停方法管理线程和停止事件；打开时确保监控存活，退出时在 `finally` 重置状态。增加“启动时关闭后打开”和“开启→关闭→再次开启”两种回归场景。

**11. [P2] glob 查找不符合工具声明的路径模式语义**

位置：`fs.py:42`、`fs.py:49`、`fs.py:57`。

实现只要模式没有 `**` 就停止遍历子目录，使 `src/*.ts` 永远搜不到 `src` 中的文件；而 `fnmatch` 不会把 `**/` 解释为“零层或多层目录”，`src/**/*.ts` 会漏掉 `src` 的直接子文件。结果将误导 AI 判断文件是否存在。

复现：临时目录包含 `src/index.ts` 和 `src/nested/inner.ts`。`src/*.ts` 返回空；`src/**/*.ts` 只返回嵌套文件。

建议：使用支持路径层级与 `**` 的 glob 实现，再施加忽略目录、数量上限和排序规则。覆盖零层、单层、多层目录及 Windows 路径分隔符的测试。
